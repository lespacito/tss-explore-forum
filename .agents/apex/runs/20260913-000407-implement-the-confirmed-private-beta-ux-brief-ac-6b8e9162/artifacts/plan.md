# APEX implementation plan

Execution is direct because route, type, copy and shared-style changes are tightly coupled. Independent agents are reserved for the required adversarial review after integration.

Order: data contracts and civic shell → continuous creation and follow-up surfaces → current tests/docs → static validation and detector → adversarial review → fixes → runtime proof.

Re-plan on schema generation drift, route-tree incompatibility, unexpected baseline failure, overlap with user-owned files, unavailable local fixtures, recovery evidence contradicting the selected invariant, or any edit outside declared scope.

Rollback is file-scoped: migration and nullable category changes move together; route removal keeps a redirect-compatible legacy path until generated routing and browser proof pass; no production database action is authorized.
